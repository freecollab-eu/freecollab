# Device-encrypted work

Local encrypted channels and bilateral Connect rooms use the same `EncryptedWorkClient`, encrypted Matrix events and typed editor. The server stores event pointers, publication authority, coalesced notice progress and peer poll cursors. It never stores decrypted resource fields, searches them, runs their contents, or holds device keys. Changing a secure room into a native operation is not a fallback.

## Shared flows

The existing document workspace uses encrypted organization and collection adapters: stacks, document placement and relationships, saved room messages and mixed resource collections retain actual source IDs. Document comments keep their selected-passage Yjs anchors inside encrypted comment payloads. The organization reducer validates every revision's nested ownership and tombstones, including concurrent first creation. Creator/admin edits require actual verified publication authority; a client-supplied role is never sufficient.

The shared-work surface supports project colors, tasks linked to projects/files/decisions, current globally named assignees, dates/checklists, feed posts, decisions, collections, encrypted file upload/download, HTTPS links and resource comments. The retained calendar and Yjs document flows use the original real resource reader/editor. Global `@` selection and `/` tools share the same inputs. Selected reference spans bind exact full Matrix identities or room resource IDs; editing a label detaches the reference. Document references use relative Yjs positions and survive concurrent text insertion. Peer passage comments open below the actual shared Yjs editor, store the exact selected passage anchor inside ciphertext, and resolve it against verified current document state. Comments retain their original author/text/target/anchor; only their creator may resolve or archive them. A foreign forged comment/workflow update is quarantined without blocking the legitimate owner’s verified history.

Cross-installation IDs are connection + authenticated author namespace + UUID, with the reserved document-organization singleton as the sole multi-creator root. Resource navigation includes both exact kind and ID. Local native records are not manufactured for peer resources. ACL checks resolve actual current catalogs/events before a new reference is used. Unchanged references retain only exact rebased spans from newly verified prior content, so a former participant does not make unrelated text edits impossible. New identities, duplicated mentions, changed labels or forged historical spans still require current access; opening any target always rechecks current authority. Missing keys, unverifiable authors, stale scope, unsupported schemas and unavailable peers fail closed and remain visible as warnings or incomplete versions.

## Workflows and disclosure

Reviewed encrypted workflows contain 1–12 typed task/feed/decision steps. A participant explicitly starts a run on their verified device; the encrypted run snapshots the reviewed plan and owner. Every output has a deterministic ID and origin receipt. Acknowledged outputs survive interruption and are recognized on resume, so retry does not duplicate them. Current grants and resource heads are checked between operations. Pause/cancel stops later operations. Closing the app stops future work until the owner explicitly continues on a verified device. There is no server background execution of opaque fields.

AI and installed external apps require a separate explicit foreground disclosure review. They cannot read encrypted room data in the background. AI previews do not automatically rewrite shared resources. Native background app queues continue to exclude encrypted plaintext. Provider credentials, SSO, local directory groups, email/invitation integration and operator policy are intentionally local, and are not federated room resources. Cross-installation `@` uses verified Matrix participants and typed resources; a local group identifier never becomes a remote identity or an implicit directory-sync grant.

## Versioning and conflict review

`freecollab-federated-work/1` remains the compatible task/calendar/document base. Signed capability negotiation enables `freecollab-federated-work/2` references, `freecollab-encrypted-work/2` additional typed resources and `freecollab-work-authority/1` historical role proofs. Legacy peers missing lists use version 1; they are not sent unnegotiated new schemas. Exact bounded validators reject unknown fields/actions rather than accepting arbitrary operations.

Scalar resources form causal revision DAGs. Concurrent heads require explicit review/merge; stale writers cannot overwrite unseen heads. Organization domain validation additionally prevents a member from changing another creator's nested stack authority. Text documents merge actual Yjs changes on verified devices, within bounded state/update budgets. Encrypted collection adapters use actual root generation and version CAS. Archival does not recall keys or erase content already seen by recipients.

## Recording publication boundary

Capture file, clip and caption transactions use reserved `fc-capture-file-`, `fc-capture-clip-` and `fc-capture-caption-` prefixes. The official Matrix SDK HTTP `fetchFn` denies these transactions unless a live foreground consent guard is registered for that exact room/transaction/account epoch. It pins the encrypted request-body digest, repeats authorization on every actual HTTP retry, and carries the consent abort signal into fetch. Completed/failed guard scopes remain denied; reload cannot silently replay a cached capture event. Attachment ciphertext upload alone does not share its encryption key; the key-bearing encrypted event must pass this boundary. Live captions require explicit review that all encrypted channel members can read them, including members outside the call. Their final HTTP guard rechecks the recorder, request generation, recipient audience and complete current consent after SDK encryption. Indexed/downloaded recording files additionally verify the encrypted recording proof. Verified recording proof additionally replays durable indexed host admissions and device joins. Home-server pointer positions—not sender timestamps or payload-claimed sequence numbers—bind the reviewed request and publication. Every device admitted at the request or admitted later before publication must be included; ejecting a device cannot hide an unconsented interval. Consent is enforced against the observed verified causal frontier; separate homeservers cannot provide globally atomic knowledge of unobserved remote revocation.

A verified stop is terminal for that reviewed recording request. Later host events cannot restart it or authorize another part with old consent; valid earlier publication receipts remain readable. Slow original reservations reconcile against the exact retained clip instead of losing the receipt at the UI timeout. Unpublished segments remain in the device's private vault with download/discard controls and a visible pending notice when leaving; they never become a server plaintext upload queue.

## Validation

Opaque peer progress polling waits at least 15 seconds between attempts, and rechecks active scope even after a failed peer request before persisting diagnostics.

Focused API tests exercise opaque HTTP storage, real signed pinned-peer control-plane requests, capability downgrade, publication-time authority, current grants after I/O, preferences, notifications and identity erasure. Node tests execute the actual typed reducer, Yjs anchors, device workflow callbacks, UI state guards and final encrypted HTTP publication guards. These tests are distinct from a real homeserver/browser proof; see the named proof artifact for that evidence and its source hashes. Neither synthetic sessions nor local verified TLS fixtures establish customer IdP, public deployment, physical client or production capacity acceptance.
